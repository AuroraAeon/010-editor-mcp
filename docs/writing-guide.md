# 反防御性文档写作指南

适用于任何项目的文档系统，包括说明、设计、规范、操作指南、任务指令、报告、复盘和自动生成的文档。

## 核心原则

文档帮助读者理解问题、判断方案或完成操作。每句话应提供事实、推进解释、指定动作，或说明影响当前判断的限制。只为预防质疑、强调作者谨慎、声明自己没有夸大而存在的句段，直接删除。

判断方法：删掉这句话，读者的理解、决定或操作是否改变？若不改变，删除。

## 保留有用的限制

限制紧接它影响的结论，写清三个要素：缺少什么信息、影响哪个判断、如何解决。解决办法未知时，直接说明缺口。

例如：“日志没有记录请求耗时，暂时无法定位延迟发生在哪个阶段；下一次运行增加阶段计时。”

安全要求、权限条件、适用范围和失败处理应给出具体规则。每项在对应规范中定义一次，其他文档引用。

## 清晰表达

借鉴ASD-STE100的清晰表达原则：

- 一句表达一个主要意思，长句按因果或步骤拆开。
- 明确主语和动作，用“比较两个版本的响应时间”代替“开展相关性能核验工作”。
- 同一概念使用同一术语，缩写首次出现时解释。
- 用可核对的条件、数值、字段、路径和命令表达要求。
- 删除空泛强调、自我评价、重复承诺和身份声明。
- 优先直接陈述事实；否定句用于明确禁止事项或排除会影响操作的错误理解。
- 区分事实、推断和建议，用来源与推理过程说明区别。

中文按信息单元拆句。公式、接口、字段和命令保留精确形式。

## 文档系统的职责

| 文档类型 | 主要内容 |
|---|---|
| 项目入口 / 索引 | 当前状态、常用入口、文档导航 |
| 规范 / 接口 | 要求、适用范围、字段、条件、失败处理 |
| 设计 / 提案 | 问题、依据、方案、取舍、验证标准 |
| 操作指南 / 任务指令 | 前提、步骤、完成条件、故障处理 |
| 报告 / 复盘 | 结论、证据、原因、后续动作 |
| 执行记录 | 进度、决定、阻塞、下一步 |

文件名和目录按项目需要选择。共用规则集中维护，具体任务引用；任务指令只写执行所需内容，详细参数和论证放在设计中。

现行入口更新为当前状态，历史记录保留日期。用历史索引连接旧记录，避免反复追加“此前状态已失效”。

移动或重命名文档时，同步更新链接、任务指令和生成器引用。已发布、签署或受完整性校验保护的原件按项目保存要求保留；修订通过新版本及变更记录表达。

## 改写示例

| 防御性表述 | 改写 |
|---|---|
| 本次没有部署、发布或上传，不声称已经成功 | 需要状态时写“方案待验证”；其余删除 |
| 测试通过不代表所有环境都有效，也不能保证未来没有问题 | “已在Windows和Linux验证；macOS待验证” |
| 不得挑选最好看的结果来宣称方案正确 | “按预先确定的响应时间和错误率标准比较全部方案” |
| 我们并不是忽略风险，也没有盲目采用该方案 | 写出影响决定的风险及处理方式；删除身份辩解 |
| 不能把这次故障全部归因于网络 | “断网前已出现队列积压，先检查消费者吞吐” |

## 交稿检查

先检查结论和动作是否明确，再核对事实、来源、链接和执行条件。逐句删除不改变读者判断或操作的内容。保留必要的条件与限制，放在它们实际影响的位置。
